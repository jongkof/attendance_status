# Copilot 프롬프트 제공

## 함께 읽을 자료

- [PRODUCT.md](../../../PRODUCT.md): 관리자가 "서비스가 제공하는 날짜가 채워진 프롬프트"로 Copilot에 근태를 정리하게 한다는 핵심 흐름과, 서비스가 프롬프트와 템플릿을 제공한다는 약속을 정한다.
- [GLOSSARY.md](../../../GLOSSARY.md): 근태 JSON, 수신 시각, 근태 유형, 팀원 명단의 뜻을 정한다.
- [attendance-json-import 스펙](../attendance-json-import/spec.md)과 [sample-2026-10-26.json](../attendance-json-import/sample-2026-10-26.json): 프롬프트가 만들어야 하는 JSON의 형식과 반영 규칙(수신 시각 우선, 같은 시각이면 뒤의 레코드, `rangeStart`·`rangeEnd`·`generatedAt`은 반영에 쓰지 않음)을 정한다.
- [roster-management 스펙](../roster-management/spec.md): 명단에 없는 이름은 반영하지 않는다는 규칙과 재직 중인 팀원만 명단으로 본다는 규칙을 정한다.
- [prompt-template.md](prompt-template.md): 서비스가 보여 줄 프롬프트 원문이다. 이 스펙이 이 원문의 내용과 채워지는 값을 정한다.

## 사용자 결과

근태 관리자는 JSON 입력 화면에서 프롬프트를 복사해 Copilot에 붙여 넣기만 하면 된다. 날짜와 팀 명단이 이미 채워져 있어 매일 프롬프트를 고치지 않고, Copilot이 내놓은 JSON을 그대로 붙여 넣으면 형식 오류 없이 반영 화면에 읽힌다.

## 범위

### 포함

- JSON 입력 화면의 프롬프트 영역: 대상 날짜 선택, 프롬프트 미리보기, 한 번에 복사
- 프롬프트가 채우는 값: 대상 날짜(시작일·종료일)와 재직 중인 팀원 명단
- 프롬프트 원문(`prompt-template.md`)의 규칙

### 제외

- Copilot을 서비스가 직접 호출하는 기능(사내 메일과 연동하지 않는다)
- 프롬프트를 화면에서 편집하거나 저장하는 기능. 관리자는 복사해서 쓴다.
- 반영 화면이 JSON의 `period`·`time` 값을 검사하는 일(별도 개선 항목)

## 요구 동작

### 프롬프트 영역

- JSON 입력 화면에 프롬프트 영역이 있고, 처음에는 오늘 하루(시작일과 종료일이 같다)로 채워진 프롬프트가 보인다.
- 시작일과 종료일을 바꿀 수 있고, 바꾸면 프롬프트의 날짜가 바로 바뀐다. 종료일은 시작일보다 앞설 수 없다. 월요일 아침처럼 주말에 받은 메일까지 한꺼번에 정리하려면 시작일을 앞당긴다.
- "복사" 버튼을 누르면 프롬프트 전체가 복사되고 복사했다는 안내가 나온다. 복사가 막히면 실패했다는 안내와 함께 미리보기를 직접 선택해 복사하라고 알려 준다.
- 프롬프트의 팀 명단은 현재 재직 중인 팀원 이름 전부다. 이름을 고치거나 팀원을 추가·제거하면 다음에 열 때 바뀐 명단이 반영된다.
- 프롬프트 영역은 관리자 잠금 아래에 있다.

### 프롬프트의 내용

프롬프트 원문(`prompt-template.md`)이 정한 규칙을 서비스가 그대로 보여 준다. 사용자가 쓰던 프롬프트에서 바뀐 점은 다음과 같다.

- 날짜 `[2026-10-26]`을 서비스가 채운다. 하루가 아니라 기간도 정할 수 있다.
- 출력 맨 앞뒤에 코드블록을 붙이지 말라는 문구를 넣었다. 반영 화면은 붙여 넣은 글을 그대로 JSON으로 읽기 때문에 ` ```json ` 같은 울타리가 있으면 읽히지 않는다.
- 같은 사람과 날짜에 메일이 여러 개여도 지우거나 합치지 않고 모두 내놓게 했다(원문 5번 삭제). 어느 것이 유효한지는 서비스가 수신 시각으로 가르기 때문이며, Copilot이 기간 일정의 일부 날짜만 겹칠 때 잘못 지우는 것을 막는다.
- "늦게 출근 → 반반차"와 "지각 → 출근"이 충돌하던 것을 풀었다. 미리 양해받은 시간 변경은 반반차, 단순한 지각·조퇴 알림은 출근(note에 기록)이고, 구분이 안 되면 출근에 "확인 필요"를 붙인다.
- 연도 없는 날짜는 수신한 해로 읽고, 휴가 취소는 취소된 날짜만 "출근"으로 낸다.
- `receivedAt`을 모르는 메일은 레코드를 만들지 않게 했다. 반영 화면은 수신 시각이 없는 레코드를 오류로 거절하기 때문이다.
- 예시 레코드를 결과에 섞지 말라는 문구를 넣었다. 예시 이름은 명단에 없어 경고가 되지만, 결과에 섞이는 것 자체를 막는다.
- 명단을 채워 넣고 그 이름 그대로 쓰게 했다.
- 근태 메일이 없으면 `records`를 빈 배열로 내게 했다.

## 수용 기준

- JSON 입력 화면에서 프롬프트의 시작일과 종료일이 처음에는 오늘이고, 바꾸면 프롬프트 본문의 날짜와 `rangeStart`·`rangeEnd`가 같이 바뀐다.
- 종료일을 시작일보다 앞서게 하면 거절되고 이유가 보인다.
- 프롬프트의 팀 명단이 재직 중인 팀원과 같고, 제거한 팀원이나 아직 시작일이 오지 않은 팀원은 들어가지 않는다.
- "복사"를 누르면 클립보드에 프롬프트 전체가 들어가고 안내가 나온다.
- 프롬프트 본문에 코드블록 금지, 중복 제거 금지, 예시 결과 혼입 금지 문구가 있다.
- 이 프롬프트로 Copilot에 정리시킨 결과를 붙여 넣으면 형식 오류 없이 미리보기가 열린다(실제 Copilot으로 한 번 시험한다).
- 로그인하지 않은 상태로는 프롬프트 영역이 보이지 않는다.

## 정해진 제약과 이유

- **프롬프트의 JSON 형식은 반영 규칙과 어긋나지 않아야 한다.** 형식이 틀리면 관리자가 매일 손으로 고쳐야 해서 이 서비스의 존재 이유가 사라진다.
- **중복 판정은 서비스가 한다.** 수신 시각 우선 규칙이 서비스의 핵심 규칙이라, Copilot이 같은 일을 하면 기준이 둘이 된다.
- **명단은 DB에서 읽어 채운다.** 저장소에 실명을 두지 않기 위해서이고, 이름을 고쳐도 프롬프트가 따라온다.

## 가정 (근태 관리자가 바꿀 수 있음)

- 원문의 형식 규칙(8개 유형, 반차·반반차 구분, 시간 형식, 지각·조퇴 처리, 외근·외부 미팅은 출장으로 보는 규칙)은 사용자가 이미 써 본 것을 그대로 유지한다. 외근을 출장으로 보는 기준이 팀 실제와 다르면 원문을 고친다.
- 대상 날짜의 기본값은 오늘이다. 메일을 받은 날의 JSON을 매일 아침 한 번 만드는 흐름을 전제한다.
- `generatedAt`은 Copilot이 적는 값이고 반영에 쓰지 않는다. 틀려도 영향이 없다.

## 기존 동작과의 관계

- 지금 JSON 입력 화면에는 "Copilot이 출력한 JSON을 붙여 넣으세요"라는 안내만 있고 프롬프트는 없다. 이 스펙이 PRODUCT.md가 약속한 프롬프트 제공을 처음으로 채운다.
- 이름 복구([team-access 스펙](../team-access/spec.md))를 한 뒤에는 프롬프트의 명단이 실명이 되어, Copilot 결과의 이름과 명단이 맞는다. 이 스펙은 이름 복구 전에도 마스킹한 명단으로 똑같이 동작한다.
- 관리자 사용 안내([admin-manual 스펙](../admin-manual/spec.md))가 이 프롬프트를 쓰는 방법을 설명한다. 프롬프트가 먼저 있어야 안내가 정확하다.

## 미룬 결정과 위험

- 반영 화면은 `period` 값이 8개 유형의 정해진 구분(오전, 오후, 오전1 등)인지 검사하지 않는다. Copilot이 "오전 1" 같은 값을 내도 조용히 저장되어 집계에서 어긋날 수 있다. 프롬프트로 줄일 수 있을 뿐이어서, 반영 화면의 검사는 별도 개선 항목으로 남긴다.
- Copilot이 규칙을 지키는 정도는 모델과 메일 내용에 따라 달라서, 프롬프트만으로는 코드블록이나 틀린 날짜를 완전히 막지 못한다. 반영 전 미리보기가 마지막 안전망이다.
- 명단을 프롬프트에 넣으면 Copilot에 팀원 이름 전체가 전달된다. 사내 Copilot이라 외부 반출은 아니지만, 사내 정책을 확인해야 하면 명단 없이 쓰는 방식으로 줄일 수 있다.
