# 관리자 사용 안내

## 함께 읽을 자료

- [PRODUCT.md](../../../PRODUCT.md): 근태 관리자의 하루 흐름(핵심 흐름 1–6)과 관리 기능 범위를 정한다. 안내의 순서가 이 흐름을 따른다.
- [GLOSSARY.md](../../../GLOSSARY.md): 안내에서 쓰는 용어(근태 기록, 미확인, 리모트 조, 리모트 없는 주, 달력 항목, 면담, 팀 잠금, 관리자 잠금)를 정한다. 안내는 같은 단어를 쓴다.
- [copilot-prompt 스펙](../copilot-prompt/spec.md): 안내가 설명할 프롬프트 복사와 JSON 붙여 넣기 흐름을 정한다.
- [team-access 스펙](../team-access/spec.md), [admin-lock 스펙](../admin-lock/spec.md): 비밀번호 두 개와 복구 방법을 정한다. 안내에 복구 방법이 들어간다.
- [docs/decisions/admin-access.md](../../decisions/admin-access.md): 안내 화면도 관리자 잠금 아래에 둔다는 점을 정한다.

## 사용자 결과

처음 맡은 근태 관리자도 안내만 보고 하루 일과(JSON 만들기, 반영, 아침 확인, 메일 발송)와 월별 관리(리모트 조·순환, 휴일·행사, 명단, 면담)를 따라 할 수 있다. 막혔을 때 어느 화면에서 무엇을 하는지 바로 찾는다.

## 범위

### 포함

- 관리자 화면 안의 "사용 안내" 메뉴와 안내 화면
- 안내 내용: 하루 일과, 월별·연간 관리, 비밀번호와 복구, 자주 겪는 문제
- 안내에서 관리 화면 각 메뉴로 가는 링크

### 제외

- 팀원용 사용법. 이 안내는 근태 관리자 전용이다.
- 화면 캡처 이미지. 화면이 자주 바뀌므로 글과 순서 번호로 설명한다.
- 안내 내용을 화면에서 고치는 기능. 안내는 제품과 함께 배포되는 고정 글이다.
- 개발자용 문서(배포, 환경 변수, 마이그레이션 실행). 그 내용은 저장소 문서에 있다.

## 요구 동작

### 안내 화면

- 관리자 메뉴에 "사용 안내"가 있고, 관리자 잠금 아래에 있다. 로그인하지 않으면 로그인 화면으로 간다.
- 화면 위쪽에 목차가 있고, 목차 항목을 누르면 해당 절로 이동한다.
- 각 절은 "언제 하는가, 어느 메뉴에서 하는가, 단계, 확인할 것" 순서로 쓴다.
- 안내가 가리키는 메뉴 이름과 용어는 화면에 실제로 쓰이는 이름과 같다.

### 안내 내용

1. **하루 일과**: 프롬프트 복사 → Copilot에 붙여 넣어 JSON 받기 → JSON 입력 화면에 붙여 넣기 → 미리보기에서 바뀌는 칸, 명단에 없는 이름, "확인 필요"를 확인하고 반영 → 아침에 리모트 대상자와 미확인 칸 확인 → 오늘의 현황 메일 만들어 Outlook으로 발송.
2. **월별 관리**: 달 말에 다음 달 리모트 표 확인(리모트 조, 순환 규칙, 리모트 없는 주, 칸 직접 수정), 휴일·행사 등록, 면담 표시.
3. **연간 관리**: 새해가 다가올 때 정부 공휴일 등록(해마다 등록이 필요하다는 안내가 화면에도 나온다).
4. **명단 관리**: 팀원 추가·이름 수정·제거, 조 배정. 이름 수정 시 Copilot 프롬프트의 명단이 따라 바뀐다는 점.
5. **비밀번호**: 관리자 비밀번호와 팀 비밀번호의 차이, 바꾸는 방법, 잊었을 때 복구(저장된 값을 지워 처음 비밀번호로 되돌린다).
6. **자주 겪는 문제**: JSON이 읽히지 않을 때(코드블록, 잘린 붙여 넣기), 명단에 없는 이름이 나올 때, "더 최근 기록이 있어 건너뜀"이 나올 때, 메일 링크가 로그인 화면으로 갈 때, 수정 모드에서 칸이 바뀌지 않을 때.

## 수용 기준

- 로그인하지 않으면 사용 안내가 보이지 않고, 로그인하면 관리자 메뉴에서 열린다.
- 안내에 위 6개 절이 있고, 목차에서 각 절로 이동한다.
- 안내의 "하루 일과" 단계가 실제 화면의 순서와 맞는다. 문서만 보고 따라 해서 JSON 반영부터 현황 메일 복사까지 끝낼 수 있다(구현 뒤 한 번 따라 해 본다).
- 안내에 나오는 메뉴 이름이 관리자 메뉴의 이름과 같고, 링크가 맞는 화면으로 간다.
- 안내에 실명이나 실제 팀원 이름이 없다.
- 좁은 화면에서도 글이 잘리지 않고 읽힌다.

## 정해진 제약과 이유

- **안내는 앱 안의 화면이다.** 관리자는 서비스 안에서 막혔을 때 바로 확인해야 하고, 저장소 문서는 관리자가 읽지 않는다.
- **글과 번호로 쓴다.** 캡처는 화면이 바뀔 때마다 낡아서 오히려 오해를 만든다.
- **구현 순서는 맨 마지막이다.** 안내가 설명하는 화면이 모두 확정된 뒤에 써야 틀린 설명이 남지 않는다.

## 가정 (근태 관리자가 바꿀 수 있음)

- 안내는 한국어로 쓰고 한 화면의 긴 문서로 둔다. 절이 많아지면 나누는 것은 나중에 정한다.
- 안내에 쓰는 예시 이름은 "성+ㅇㅇ" 표기를 쓴다.
- 안내는 다음 스펙이 구현된 뒤의 화면을 기준으로 쓴다: 면담 표시, 개별 수정(리모트 계획·면담 편집 포함), 팀 잠금, 프롬프트 제공, 현황표 모양 개선, 리모트 표 캡처.

## 미룬 결정과 위험

- 기능이 바뀌면 안내를 같이 고쳐야 한다. 안내가 낡아도 알려 주는 장치가 없다. 기능 스펙을 구현할 때 안내의 해당 절을 함께 고치도록 각 스펙의 수용 기준을 따른다.
- 안내를 읽는 관리자가 한 명뿐이면 효과가 작을 수 있다. 사용해 보고 필요 없는 절은 줄인다.
