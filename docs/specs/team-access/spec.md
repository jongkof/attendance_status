# 팀 잠금과 이름 복구

## 함께 읽을 자료

- [PRODUCT.md](../../../PRODUCT.md): "현황 화면은 누구나 볼 수 있고 관리자 페이지만 잠근다"는 문구가 이 스펙과 맞지 않는다. 구현 전에 "현황 화면은 팀 비밀번호로, 관리자 페이지는 관리자 비밀번호로 잠근다"로 고쳐야 한다(제품 문서 수정은 이 스펙의 범위 밖이다).
- [GLOSSARY.md](../../../GLOSSARY.md): 팀 잠금, 관리자 잠금의 뜻을 정한다.
- [docs/decisions/admin-access.md](../../decisions/admin-access.md): 현황표를 팀 공용 비밀번호로 잠그기로 한 결정과 그 이유, 거절한 대안(메일 링크 토큰, 공개 유지)을 정한다. 이 스펙은 그 결정을 따른다.
- [docs/decisions/data-storage.md](../../decisions/data-storage.md): 실명 근태를 외부 서비스에 저장해도 된다는 확인을 정한다.
- [admin-lock 스펙](../admin-lock/spec.md): 관리자 잠금의 로그인 방식, 비밀번호 변경, 복구를 정한다. 팀 잠금은 같은 방식을 따르되, 그 스펙의 "공개 화면" 항목은 이 스펙이 대체한다.
- [daily-mail-body 스펙](../daily-mail-body/spec.md): 메일 본문의 현황 링크를 정한다. 링크를 열려면 로그인해야 한다는 점이 바뀐다.
- [roster-management 스펙](../roster-management/spec.md): 이름 수정 화면을 정한다. 이름 복구는 이 화면으로 한다.
- [docs/follow-ups/mail-date-lost-after-login-redirect.md](../../follow-ups/mail-date-lost-after-login-redirect.md): 로그인을 거치면 보던 날짜가 사라지는 문제다. 팀 잠금에서도 같은 문제가 현황 링크의 월에 생기므로 함께 풀어야 한다.

## 사용자 결과

우리 팀원만 현황표를 본다. 팀원은 팀 비밀번호를 한 번 입력하면 오래 로그인이 유지되고, 비밀번호를 모르는 사람은 주소를 알아도 현황표도 데이터도 볼 수 없다. 근태 관리자는 관리자 비밀번호로 로그인하면 현황표까지 함께 열리고, 팀 비밀번호를 화면에서 바꿀 수 있다. 시험 단계에서 쓰던 마스킹 이름은 관리자가 명단 관리 화면에서 직접 실명으로 바꾼다.

## 범위

### 포함

- 현황표(`/`)와 현황표가 읽는 서버 요청의 팀 잠금
- 팀 로그인 화면, 로그아웃
- 관리자 화면에서 팀 비밀번호 보기(설정됨 여부)·바꾸기
- 메일 링크로 들어왔을 때 로그인 뒤 원래 보던 월로 돌아오기
- 이름 복구 절차(명단 관리 화면에서 직접 수정)를 기록

### 제외

- 팀원별 계정과 누가 봤는지의 기록
- 로그인 시도 횟수 제한과 계정 잠금(admin-lock 스펙이 미룬 것과 같다)
- 이메일 복구
- 메일 링크에 접근 토큰 붙이기(거절한 대안, admin-access 결정 참고)
- 명단의 실명을 서비스가 대신 바꿔 주는 기능. 이름은 사용자가 화면에서 직접 고친다.

## 요구 동작

### 팀 로그인

- 로그인하지 않은 사람이 현황표를 열면 팀 로그인 화면이 나온다. 이 화면에는 현황 내용도 관리 화면으로 가는 링크도 없다.
- 팀 비밀번호가 맞으면 현황표로 이동한다. 틀리면 이유를 알려 주고 그대로 머문다.
- 팀 로그인은 30일 동안 유지되고, 만료되었거나 변조된 로그인 정보는 로그인하지 않은 것으로 다룬다.
- 현황표 화면에 로그아웃 방법이 있다.
- 팀 비밀번호로는 관리 화면에 들어갈 수 없다. 관리 화면은 관리자 비밀번호로만 들어간다.
- 관리자로 로그인한 사람은 팀 비밀번호 없이 현황표를 볼 수 있다.
- 현황 데이터를 읽는 서버 요청도 요청마다 팀 로그인 또는 관리자 로그인을 다시 확인하고, 둘 다 없으면 거절한다. 주소를 직접 호출해도 데이터가 나오지 않는다.

### 팀 비밀번호 관리

- 처음 팀 비밀번호는 서버 환경 변수로 정한다. 관리자가 화면에서 바꾸면 암호화한 값(해시)만 저장하고, 그 뒤로는 저장된 값이 환경 변수보다 우선한다. 원문은 어디에도 저장하지 않는다.
- 관리자 화면에서 새 비밀번호를 두 번 입력해 바꾼다. 바꾸면 팀원의 로그인이 모두 풀리고 다시 로그인해야 한다. 바꾼 관리자의 로그인은 풀리지 않는다.
- 잊었을 때는 admin-access 결정과 같이 저장된 한 줄을 지워 환경 변수의 처음 비밀번호로 되돌린다.
- 팀 비밀번호는 관리자 비밀번호와 달라야 한다. 같으면 거절하고 이유를 보여 준다.

### 메일 링크

- 현황 메일 본문의 링크를 로그인하지 않은 사람이 열면 로그인 화면을 거치고, 로그인한 뒤 링크가 가리킨 월의 현황표가 열린다.
- 메일 본문의 이름과 집계는 그대로 들어간다. 링크를 열지 못해도 본문만으로 현황을 알 수 있다.

### 이름 복구

- 사내 정책상 실명 근태를 외부 서비스에 저장해도 되는 것으로 확인되었다(data-storage 결정).
- 마스킹된 이름을 실명으로 되돌리는 방법은 관리자가 명단 관리 화면에서 팀원 이름을 하나씩 고치는 것이다. 이름을 고치면 그 팀원의 과거 기록과 현황표에 새 이름으로 이어진다(roster-management 스펙).
- 권장 순서는 팀 잠금을 배포한 뒤 이름을 고치는 것이다. 잠금 전에 실명을 넣으면 실명이 누구에게나 보인다.
- 이름을 고친 뒤 Copilot에는 새 이름의 명단을 쓰는 프롬프트를 써야 한다. 옛 이름이 담긴 JSON은 명단에 없는 이름으로 미리보기에 나온다(copilot-prompt 스펙이 명단을 프롬프트에 채운다).
- 실명은 저장소의 코드, 문서, 샘플 JSON, 커밋에 넣지 않는다. 저장소의 시험 데이터는 마스킹한 이름 그대로 둔다.

## 수용 기준

- 로그인하지 않은 브라우저로 현황표를 열면 팀 로그인 화면이 나오고 현황 내용은 보이지 않는다.
- 맞는 팀 비밀번호를 넣으면 현황표가 열리고, 틀리면 열리지 않는다.
- 팀 비밀번호로 로그인한 상태에서 `/admin`을 열면 관리자 로그인 화면으로 간다.
- 관리자로 로그인한 상태에서는 팀 로그인 없이 현황표가 열린다.
- 로그인하지 않은 상태로 현황 데이터를 읽는 요청을 직접 보내면 거절된다.
- 팀 비밀번호를 바꾸면 이미 로그인해 있던 팀원 브라우저는 다음 요청에서 로그인 화면으로 돌아가고, 새 비밀번호로만 로그인된다. 바꾼 관리자는 계속 로그인되어 있다.
- 팀 비밀번호를 관리자 비밀번호와 같은 값으로 바꾸려 하면 거절된다.
- 현황 메일의 링크(예: 11월 현황)를 로그아웃된 브라우저에서 열고 로그인하면 11월 현황표가 열린다.
- 로그인한 지 30일이 지난 로그인 정보로는 현황표가 열리지 않는다.
- 저장된 팀 비밀번호 한 줄을 지우면 환경 변수의 처음 비밀번호로 다시 로그인된다.
- 명단 관리 화면에서 이름을 바꾸면 현황표의 해당 팀원 행이 새 이름으로 보이고 과거 달도 이어진다.

## 정해진 제약과 이유

- **팀 공용 비밀번호 하나로 잠근다.** 기존 잠금 구조를 재사용하고 팀원의 이메일 같은 개인정보를 더 받지 않는다. 근거와 거절한 대안은 admin-access 결정을 따른다.
- **관리자 비밀번호와 따로 둔다.** 팀원 모두가 아는 비밀번호로 관리 기능이 열리면 안 된다.
- **서버 요청마다 다시 검사한다.** 화면만 잠그면 주소를 직접 호출해 데이터를 볼 수 있다.
- **이름은 사용자가 직접 바꾼다.** 실명이 저장소와 대화 기록에 남지 않게 하기 위해서다.

## 가정 (근태 관리자가 바꿀 수 있음)

- 팀 로그인 유지 기간은 30일이다. 팀원이 매일 여는 서비스라 자주 다시 입력하게 하면 접속이 줄어든다고 보았다. 관리자 잠금의 12시간과 다른 값이다.
- 관리자 로그인은 현황표도 연다. 관리자도 팀원이기 때문이다.
- 팀 비밀번호 변경은 관리자 화면의 비밀번호 메뉴 안에 둔다. 위치는 구현에서 정한다.
- 팀 비밀번호 환경 변수는 배포 설정에 새로 추가해야 한다. 값이 없으면 현황표를 열 수 없다.

## 기존 동작과의 관계

- PRODUCT.md의 "현황 화면은 누구나 볼 수 있고 관리자 페이지만 잠근다"와 admin-lock 스펙의 "공개 현황표는 로그인 없이 누구나 열 수 있다" 항목이 이 스펙으로 바뀐다. 두 문서는 구현 전에 고친다.
- 이미 만든 "공개 현황표"라는 이름이 코드와 화면 문구에 남아 있다. 팀 잠금 뒤에는 "현황표"로 부르고, 문구 정리는 구현에서 한다.
- 메일은 서비스가 보내지 않고 관리자가 복사해 Outlook으로 보낸다. 링크를 열 때만 로그인이 필요해진다.

## 미룬 결정과 위험

- **로그인 시도 제한:** 인터넷에 열린 로그인 화면이 하나 늘어난다. 팀 비밀번호는 여러 사람이 알아 추측 공격이 쉬운 편이므로, 길고 추측하기 어려운 값을 쓰는 것으로 위험을 줄인다. 시도 제한은 공개 서비스 위험 점검 때 정한다.
- 팀원이 퇴사하면 비밀번호를 바꾸고 팀에 다시 알려야 한다. 팀원 수가 늘면 이 부담이 커진다.
- 비밀번호가 팀 밖으로 새도 누가 새었는지 알 수 없다.
- 잠금은 보는 사람을 줄일 뿐이다. 데이터는 여전히 외부 서비스에 있으며, 이 점은 사내 정책 확인으로 허용된 것으로 본다.
- 이름을 고친 사이에 받은 근태 JSON은 옛 이름이라 명단에 없는 이름으로 나올 수 있다. 이름 복구는 근태 JSON을 반영하지 않는 시간(아침 전 등)에 한꺼번에 하는 것이 좋다.
