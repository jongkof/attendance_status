# 공휴일 미등록 연도 안내

## 함께 읽을 자료

- [PRODUCT.md](../../../PRODUCT.md): 정해진 규칙의 휴일은 자동으로 보이고 정부 공휴일은 관리자가 등록한다는 전제, 관리자 화면을 잠그는 범위를 정한다. 일괄 입력 문구는 이 스펙에 맞춰 고쳤다.
- [docs/decisions/holiday-source.md](../../decisions/holiday-source.md): 정부 공휴일이 달력 항목으로 저장되고 처음 데이터가 2026–2027년이라는 점, 연도별 등록을 하루씩 한다는 결정을 정한다. 이 스펙의 결정을 함께 적었다.
- [holidays-and-events 스펙](../holidays-and-events/spec.md): 달력 편집 화면(`/admin/calendar`)과 휴일 표시를 정한다. 이 스펙은 그 화면과 관리자 현황표, 메일 미리보기에 안내를 더한다.
- [daily-mail-body 스펙](../daily-mail-body/spec.md): 메일 미리보기 화면의 구성을 정한다.
- [docs/decisions/admin-access.md](../../decisions/admin-access.md): 관리자 화면을 잠그는 규칙을 정한다. 안내는 모두 관리자 화면 안에만 나온다.

## 사용자 결과

2028–2030년 정부 공휴일은 미리 넣어 두고, 2031년처럼 아직 등록되지 않은 해를 관리자가 보게 되면 공휴일이 출근으로 잘못 보이기 전에 화면이 먼저 알려 준다. 알림에는 등록하는 방법이 단계별로 적혀 있어서, SQL을 한 번도 실행해 본 적이 없는 관리자도 그대로 따라 할 수 있다.

## 범위

### 포함

- 2028–2030년 정부 공휴일(설날·추석 4일, 대체공휴일 포함)을 공식 자료와 대조해 SQL 파일로 만들어 두는 일. 기존 2026–2027년 처음 데이터와 같은 방식이고, 사용자가 SQL Editor에서 실행한다.
- 정부 공휴일이 등록되지 않은 연도를 보고 있을 때 나오는 안내
- 새해가 다가오면 다음 해가 등록되지 않았음을 미리 알리는 안내
- 안내에 붙는 두 가지 등록 방법의 단계별 설명(달력 편집 화면에서 하나씩, 준비된 SQL 파일을 SQL Editor에서 한 번에)

### 제외

- 휴일·행사를 여러 건 한 번에 입력하는 템플릿과 프롬프트. 만들지 않기로 했다(아래 "설정한 결정").
- 앱 안에서 SQL을 만들거나 실행하는 기능. SQL 파일은 개발 쪽에서 준비하고, 앱은 안내만 한다.
- 2031년 이후 공휴일 데이터. 안내가 뜰 때 그 해 SQL을 만든다.
- 공공데이터 API 자동 가져오기(holiday-source 결정의 재검토 조건이 생길 때 다시 본다)
- 공개 현황표의 안내. 안내는 관리자에게만 보인다.

## 요구 동작

### 안내가 나오는 조건

- 어떤 연도에 저장된 휴일(달력 항목의 휴일)이 하나도 없으면 그 연도는 "공휴일 미등록"이다. 회사 규정 휴일은 계산으로 보이는 것이라 저장된 휴일에 세지 않는다.
- 관리자 화면에서 미등록 연도의 날짜를 보고 있을 때 안내가 나온다. 안내가 나오는 화면은 달력 편집 화면, 관리자 현황표, 현황 메일 미리보기다.
- 11월 1일부터는 다음 해가 미등록이면, 보고 있는 연도와 상관없이 같은 관리자 화면들에 "내년 공휴일이 아직 등록되지 않았습니다"를 알린다.
- 등록된 휴일이 한 건이라도 있는 연도는 등록된 것으로 본다(일부만 등록된 경우는 알아채지 못한다. 아래 "남은 위험").
- 공개 현황표에는 안내가 나오지 않는다.

### 안내 내용

- 한 문장으로 무엇이 문제인지 말한다. 예: "2031년 공휴일이 아직 등록되지 않아 공휴일이 출근으로 보일 수 있습니다."
- 그 아래에 "등록 방법 보기"를 눌러 펼치는 설명이 있고, 접어 두면 한 줄만 보인다. 한 번 펼친 설명은 같은 화면에서 다시 접을 수 있다.
- 설명에는 두 가지 방법이 있고, 어느 쪽이든 끝나면 이 화면을 새로 고쳐 안내가 사라졌는지 확인하라고 적는다.

### 방법 1: 달력 편집 화면에서 하나씩 등록

설명은 번호 단계로 쓴다. 관리자 화면 머리글의 달력 편집으로 이동, 그 연도 선택, 날짜와 이름과 종류(휴일)를 입력해 추가, 모든 공휴일을 넣을 때까지 반복(설날·추석은 앞뒤 날까지 4일), 마지막에 현황표에서 휴일 칸이 회색으로 보이는지 확인하는 순서다. 연도 하나에 20건 안팎임을 알려 준다.

### 방법 2: 준비된 SQL 파일을 한 번에 실행

설명은 번호 단계로 쓴다. 개발 담당자에게 해당 연도의 공휴일 SQL 파일을 받는다(파일 이름 형식과 받는 곳을 안내에 적는다), Supabase 대시보드에 로그인해 이 서비스의 프로젝트를 연다, 왼쪽 메뉴의 SQL Editor를 연다, 새 쿼리를 만들어 파일 내용을 모두 붙여 넣는다, Run을 누른다, 성공 메시지("Success")를 확인한다, 이 서비스의 달력 편집 화면을 새로 고쳐 그 연도의 휴일이 보이는지 확인한다. 같은 SQL을 두 번 실행해도 같은 날짜가 중복되지 않는다는 점과, 오류가 나면 아무것도 들어가지 않으니 그대로 개발 담당자에게 오류 문구를 전달하라는 점도 적는다.

### 연도별 SQL 파일

- 새 연도의 공휴일 SQL은 개발 쪽에서 공식 자료와 대조해 만든다. 같은 날짜가 이미 있으면 건너뛰도록 만들어 두 번 실행해도 안전하다.
- 파일을 언제 만들지는 이 스펙이 정하지 않는다. 안내가 11월부터 뜨므로 그 전에 준비하는 것이 좋다.

## 수용 기준

- 저장된 휴일이 없는 연도(예: 2031년)의 달력 편집 화면, 관리자 현황표, 메일 미리보기에 안내가 나오고, 저장된 휴일이 있는 연도(2026–2030)에는 나오지 않는다.
- 2028–2030년 SQL을 실행하면 각 연도의 정부 공휴일이 현황표에 회색 휴일로 보인다. 설날·추석은 앞뒤 날까지 4일이고, 대체공휴일이 필요한 해는 포함된다. 같은 SQL을 두 번 실행해도 중복되지 않는다.
- 공개 현황표에는 어느 연도에도 안내가 나오지 않는다.
- 11월 1일 이후에 다음 해가 미등록이면 관리자 화면 세 곳에 내년 안내가 나오고, 10월 31일까지는 나오지 않는다.
- "등록 방법 보기"를 누르면 두 방법의 번호 단계가 펼쳐지고 다시 누르면 접힌다.
- 달력 편집 화면에서 미등록 연도에 휴일을 하나 등록하면 안내가 사라진다.
- 로그인하지 않으면 안내가 보이는 관리자 화면에 들어갈 수 없다(기존 관리자 잠금 그대로).

## 설정한 결정

- 휴일·행사 일괄 입력(템플릿과 프롬프트, 날짜 범위 등록)은 만들지 않는다. 연도 하나에 20건 안팎이고 해마다 한 번뿐이라 하루씩 등록하거나 준비된 SQL로 충분하며, 만들고 유지하는 비용이 더 크다는 판단이다. 이 결정은 holiday-source 결정에 적었다.
- 위험은 입력의 번거로움이 아니라 등록을 잊는 것이므로, 입력 도구 대신 미등록 안내로 막는다.

## 가정(바꿀 수 있음)

- "내년" 안내는 11월 1일부터 시작한다. 새해 전에 SQL을 준비할 시간을 두기 위해서다.
- 안내는 달력 편집 화면, 관리자 현황표, 메일 미리보기에만 나오고, 다른 관리자 화면(JSON 입력, 리모트 등)에는 나오지 않는다.
- SQL 파일은 개발 담당자가 만들어 주고 관리자는 실행만 한다. 관리자가 SQL을 직접 쓰는 일은 없다.
- SQL Editor 화면 이름과 버튼(SQL Editor, New query, Run)은 현재 Supabase 대시보드 기준이다. 화면이 바뀌면 설명을 고친다.
- 안내 설명에서 개발 담당자에게 파일을 받는 방법(받는 곳, 파일 이름 형식)은 구현 때 저장소의 실제 위치에 맞춰 적는다.

## 미룬 결정과 위험

- **일부만 등록된 연도:** 휴일이 한 건이라도 있으면 등록된 것으로 보므로, 예를 들어 설날만 넣고 추석을 빠뜨려도 안내가 나오지 않는다. 연도별 건수 기준(예: 공식 목록과 대조)은 필요해지면 정한다.
- **임시공휴일:** 새로 생긴 임시공휴일은 앱이 알 수 없다. 안내가 해결해 주지 않는다. 관리자가 그때그때 등록해야 한다.
- **SQL 실행 위험:** 관리자가 잘못된 SQL을 붙여 넣으면 다른 데이터가 바뀔 수 있다. 안내는 개발 담당자에게 받은 파일만 쓰라고 적는다.
- **2028–2030년 데이터의 정확도:** 설날·추석·부처님오신날은 음력이라 공식 자료(한국천문연구원 월력요항 등)와 대조해서 넣고, 대체공휴일은 현행 법령 기준으로 계산한다. 미리 넣는 데이터라 법이 바뀌거나 임시공휴일이 생기면 달라질 수 있고, 총선·지방선거일 같은 선거일은 법정 날짜가 확인될 때만 넣는다. 틀리면 관리자가 달력 편집 화면에서 고친다.
- **먼 해의 데이터:** 2030년까지 넣으면 2031년부터 안내가 뜨므로 안내가 자주 쓰이지는 않는다. 그래도 안내는 유지한다(임시공휴일 누락과 일부만 등록된 해는 못 알아채지만, 완전히 비어 있는 해는 막는다).
