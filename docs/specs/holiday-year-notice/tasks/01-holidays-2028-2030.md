# 01 — 2028–2030 공휴일 데이터

## Outcome

2028년부터 2030년까지의 정부 공휴일(설날·추석 4일, 대체공휴일 포함)이 달력 항목으로 DB에 들어가 있어, 관리자가 따로 등록하지 않아도 그 해 현황표에 휴일이 회색으로 보인다. 데이터는 공식 자료와 대조해 SQL 파일로 만들고 사용자가 SQL Editor에서 실행한다.

## Blockers

None.

## Acceptance criteria

- [ ] 2028, 2029, 2030년 각각의 정부 공휴일이 SQL 파일 하나에 들어 있다. 신정, 설날 4일(명절 전일·당일·익일·그 익일), 3·1절, 어린이날, 부처님오신날, 현충일, 제헌절, 광복절, 추석 4일, 개천절, 한글날, 성탄절과 법령상 대체공휴일이 연도별로 포함된다.
- [ ] 같은 SQL을 두 번 실행해도 같은 날짜가 중복되지 않고 오류도 나지 않는다.
- [ ] 선거일과 임시공휴일은 법정 날짜가 공식 자료로 확인될 때만 들어간다. 확인되지 않은 항목은 넣지 않고 그 사실을 완료 보고에 적는다.
- [ ] 음력 휴일(설날, 부처님오신날, 추석)의 날짜와 대체공휴일 날짜는 공식 자료와 일치하고, 출처를 SQL 파일 주석이나 완료 보고에 적는다.
- [ ] 사용자가 SQL을 실행하면 달력 편집 화면(`/admin/calendar?year=2028` 등)에 연도별 항목이 날짜순으로 보이고, 해당 연도의 현황표에서 그 날짜가 휴일 음영과 빨간 날짜로 보인다.

## Constraints

- 휴일 데이터의 출처와 저장 방식은 `docs/decisions/holiday-source.md`를 따른다. 외부 공휴일 라이브러리나 서비스를 쓰지 않고, 저장된 달력 항목으로 넣는다. 회사 규정 휴일(근로자의 날, 회사·노조 창립기념일)은 규칙으로 계산되므로 넣지 않는다.
- SQL은 `supabase/migrations/`에 기존 파일 이름 형식으로 추가하고, 사용자가 Supabase SQL Editor에서 실행한다. 완료 보고에 파일 이름과 실행 방법을 적는다. 실행은 사용자가 한다.
- 달력 항목의 `(날짜, 종류)`가 유일하다는 기존 제약에 맞춰 중복을 건너뛰는 방식으로 쓴다.

## Verification

- 데이터 검사 테스트: SQL 파일을 읽어 연도별 건수, 설날·추석이 연속된 4일인지, 대체공휴일이 해당 공휴일이 주말·겹침일 때만 있는지, 날짜 형식이 올바른지, 중복이 없는지를 확인한다.
- 사용자가 SQL을 실행한 뒤 `/admin/calendar`에서 2028–2030년 항목이 보이는지, 한 해의 현황표(예: 2028년 10월)에서 휴일 칸이 회색으로 보이는지를 화면으로 확인한다. 이 확인은 사용자가 SQL을 실행해야 가능하다.
