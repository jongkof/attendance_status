# 관리자 잠금

## 함께 읽을 자료

- [PRODUCT.md](../../../PRODUCT.md): 현황 화면은 누구나 보고 관리자 페이지만 잠근다는 제품 경계를 정한다.
- [GLOSSARY.md](../../../GLOSSARY.md): 관리자 잠금, 근태 관리자, 미확인의 뜻을 정한다.
- [docs/decisions/admin-access.md](../../decisions/admin-access.md): 공용 비밀번호 하나, 서명된 쿠키 세션, 서버 요청마다 다시 검사, 화면에서의 비밀번호 변경(해시만 저장), 대시보드에서 저장된 값을 지우는 복구 방식을 정한다. 이 스펙은 그 결정을 따른다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md): 로그인 화면의 구성 요소와 상태 표현을 정한다.
- [attendance-json-import 스펙](../attendance-json-import/spec.md)과 [unconfirmed-attendance-mark 스펙](../unconfirmed-attendance-mark/spec.md): 이 작업이 잠그는 관리 화면과 서버 요청, 그리고 그 두 스펙에 적힌 "임시로 잠기지 않음"을 정한다. 이 작업이 그 임시 동작을 대체한다.

## 사용자 결과

근태 관리자만 비밀번호로 로그인해 근태 JSON 반영과 미확인(`?`) 표시를 할 수 있고, 관리자 화면에서 비밀번호를 직접 바꿀 수 있다. 팀원은 로그인 없이 공개 현황표를 보기만 하고, 로그인하지 않은 사람이 주소를 알아도 관리 화면을 열거나 서버에 직접 요청해 근태를 바꿀 수 없다.

## 범위

### 포함

- 관리자 로그인 화면, 로그아웃
- `/admin` 아래 모든 화면(관리자 현황표, 근태 JSON 반영, 비밀번호 변경)의 잠금
- 미리보기, 반영, 미확인 켜고 끄기, 비밀번호 변경 요청이 로그인 여부를 서버에서 다시 검사
- 관리자 화면에서 비밀번호 변경(현재 비밀번호 확인, 해시만 저장)
- 비밀번호를 잊었을 때 저장된 값을 지워 처음 비밀번호로 되돌리는 복구
- 비밀번호가 설정되지 않았을 때 아무도 들어갈 수 없는 안전한 동작

### 제외

- 관리자별 계정, 누가 언제 바꿨는지의 기록
- 관리자 이메일 등록과 이메일로 비밀번호를 되찾는 기능(현황 메일 발송 작업에서 메일 서비스와 함께 정한다)
- 로그인 시도 횟수 제한 강화(틀리면 잠시 기다리게 하는 최소한만 둔다)
- 아직 만들지 않은 관리 기능(개별 수정, 휴일·행사, 명단, 발송). 나중에 만들 때 같은 잠금을 쓴다.

## 요구 동작

### 로그인과 로그아웃

- 로그인하지 않은 사람이 `/admin` 아래 어느 화면을 열려 하면 로그인 화면으로 이동하고, 로그인에 성공하면 원래 가려던 화면이 열린다.
- 로그인 화면에는 비밀번호 입력과 로그인 버튼이 있다. 올바른 비밀번호를 내면 관리 화면이 열리고, 새로 고치거나 다른 관리 화면으로 옮겨 가도 로그인이 유지된다.
- 틀린 비밀번호는 "비밀번호가 맞지 않습니다" 같은 안내만 보여 주고 관리 화면을 열지 않는다. 비밀번호가 비어 있어도 마찬가지다.
- 틀린 시도가 있으면 다음 시도까지 잠시(1초 안팎) 기다리게 한다.
- 관리 화면에는 로그아웃이 있고, 로그아웃하면 관리 화면과 관리 요청에 다시 접근할 수 없다.
- 로그인은 12시간이 지나면 만료되어 다시 로그인해야 한다. 변조되었거나 만료된 로그인 정보는 로그인하지 않은 것으로 다룬다.

### 비밀번호 변경과 복구

- 관리자 화면 머리글에 비밀번호 변경으로 가는 링크가 있다. 변경 화면에는 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 입력이 있다.
- 현재 비밀번호가 맞아야 바뀐다. 틀리면 안내만 나오고 바뀌지 않는다.
- 새 비밀번호는 10자 이상이어야 하고, 확인 입력과 같아야 하며, 현재 비밀번호와 달라야 한다. 어긋나면 이유를 알려 주고 바뀌지 않는다.
- 바뀌면 이미 로그인한 세션은 모두 풀리고 로그인 화면으로 이동한다. 그 뒤로는 새 비밀번호로만 로그인되고, 이전 비밀번호(처음 비밀번호 포함)로는 로그인되지 않는다.
- 새 비밀번호의 원문은 어디에도 저장하지 않고, 암호화한 값(해시)만 저장한다.
- 비밀번호를 잊었을 때는 Supabase 대시보드에서 저장된 비밀번호 한 줄을 지운다. 그러면 서버 환경 변수의 처음 비밀번호로 다시 로그인된다.

### 서버 요청 잠금

- 근태 JSON 미리보기, 반영, 미확인 켜고 끄기, 비밀번호 변경은 요청마다 서버가 로그인 여부를 확인한다. 로그인하지 않은 요청은 거절되고 아무것도 저장되지 않으며, 로그인이 필요하다는 안내를 돌려준다.
- 이 거절은 화면에서 버튼이 눌리는지와 상관없이 주소를 직접 호출해도 같다.

### 공개 화면

- 공개 현황표(`/`)는 로그인 없이 누구나 열 수 있고, 관리 화면으로 가는 링크는 보이지 않는다. 지금과 같다.

### 설정되지 않은 경우

- 서버 환경 변수에도, 저장된 값에도 관리자 비밀번호가 없으면 누구도 로그인할 수 없다. 로그인 화면에는 비밀번호 설정이 필요하다는 안내가 나오고 관리 화면은 열리지 않는다.

## 수용 기준

1. 로그인하지 않고 `/admin`과 `/admin/import`를 열면 로그인 화면으로 이동한다.
2. 올바른 비밀번호를 내면 요청했던 화면(`/admin/import` 등)이 열리고, 새로 고쳐도 유지된다.
3. 틀린 비밀번호와 빈 비밀번호는 안내만 나오고 관리 화면이 열리지 않는다.
4. 로그아웃하면 `/admin`이 다시 로그인 화면으로 이동하고, 같은 브라우저에서 이전 관리 요청도 거절된다.
5. 로그인하지 않은 상태로 서버에 직접 요청하면 미리보기, 반영, 미확인 토글이 모두 거절되고 데이터가 바뀌지 않는다.
6. 로그인한 상태에서는 지금까지의 기능(JSON 미리보기·반영, 미확인 토글, 월 이동)이 그대로 동작한다.
7. 로그인 정보가 변조되었거나 만료되었으면 로그인하지 않은 것으로 다루고 거절한다.
8. 공개 현황표는 로그인 여부와 상관없이 같은 내용을 보여 주고, 관리 링크가 없다.
9. 환경 변수에도 저장된 값에도 관리자 비밀번호가 없는 서버에서는 어떤 비밀번호로도 로그인되지 않고 설정 안내가 나온다.
10. 비밀번호 변경 화면에서 현재 비밀번호가 틀리면 바뀌지 않는다.
11. 새 비밀번호가 10자 미만이거나, 확인과 다르거나, 현재 비밀번호와 같으면 이유가 안내되고 바뀌지 않는다.
12. 올바르게 바꾸면 로그인 화면으로 이동하고, 새 비밀번호로는 로그인되며 이전 비밀번호로는 로그인되지 않는다. 바꾸기 전에 로그인해 둔 다른 세션도 거절된다.
13. 데이터베이스에는 비밀번호 원문이 없고 암호화한 값만 저장되어 있다.
14. 저장된 비밀번호 한 줄을 지우면 환경 변수의 처음 비밀번호로 다시 로그인된다.
15. 로그인하지 않은 상태로 비밀번호 변경을 서버에 직접 요청하면 거절되고 바뀌지 않는다.

## 정해진 제약과 이유

- **공용 비밀번호 하나로 잠근다.** 관리자 수가 적고 변경 기록의 요구가 없으며, 이메일 같은 개인정보를 외부 서비스에 더 두지 않으려는 것이다. 근거와 재검토 조건은 admin-access 결정을 따른다.
- **서버 요청마다 다시 검사한다.** 화면을 가리는 것만으로는 주소를 직접 호출하는 요청을 막지 못하기 때문이다.
- **비밀번호 원문은 어디에도 저장하지 않는다.** 처음 비밀번호는 서버 환경 변수에 두고, 화면에서 바꾼 뒤에는 암호화한 값만 데이터베이스에 둔다. 저장소와 브라우저 코드에는 들어가지 않는다.
- **이메일 복구는 이번에 만들지 않는다.** 메일을 보내는 외부 서비스와 관리자 이메일 저장이 함께 필요해서, 그 둘을 정하는 현황 메일 발송 작업으로 미뤘다.

## 가정 (근태 관리자가 바꿀 수 있음)

- 로그인 유지 시간은 12시간이다. 매일 아침 쓰는 흐름에서 하루 한 번쯤 다시 로그인하는 정도로 잡았다.
- 로그인 화면의 주소는 `/admin/login`이다. 관리 화면에서 쓰는 이름과 같은 영역에 둔다.
- 비밀번호 변경 화면의 주소는 `/admin/password`이고, 새 비밀번호의 최소 길이는 10자다. 그 밖의 조합 규칙(숫자·기호 요구)은 두지 않는다.
- 틀린 시도 뒤의 기다림은 1초 안팎이며, 시도 횟수를 세어 막지는 않는다.
- 로그아웃은 관리 화면 머리글에 둔다.

## 미뤄 둔 결정

- **관리자 이메일 등록과 이메일 복구:** 현황 메일 발송 작업에서 메일 서비스와 함께 정한다. 그때까지의 복구는 대시보드에서 저장된 값을 지우는 방식이다.
- **관리자별 계정과 변경 기록:** 필요해지면 admin-access 결정을 다시 연다.
- **시도 횟수 제한과 계정 잠금:** 공개 서비스로 운영할 때 위험을 보고 정한다.

## 남은 위험

- 비밀번호가 유출되면 누구나 근태를 바꿀 수 있다. 화면에서 바꿀 수 있지만, 이미 유출된 비밀번호로 먼저 들어온 사람이 비밀번호를 바꿔 버릴 수도 있다. 그때는 대시보드에서 저장된 값을 지워 되돌린다.
- 비밀번호를 잊었을 때 Supabase 대시보드에 들어갈 수 있는 사람이 있어야 복구된다.
- 암호화한 값이 데이터베이스에 저장된다. 데이터베이스가 새면 그 값으로 비밀번호를 추측당할 수 있어, 추측하기 어려운 긴 비밀번호가 전제다.
- 시도 횟수를 막지 않아 외부에서 비밀번호를 추측하는 시도에 약하다. 길고 추측하기 어려운 비밀번호를 쓰는 것이 전제다.
- 외부 서비스(Vercel 등)에 올릴 때는 그곳의 환경 변수에도 관리자 비밀번호를 설정해야 하고, 로그인 정보가 안전하게 전달되려면 HTTPS가 필요하다.
- 누가 바꿨는지 알 수 없다.
- 관리자 비밀번호 설정은 사용자가 직접 해야 한다. 설정하기 전에는 실제 로그인 동작을 검증할 수 없다.
- 비밀번호를 저장할 표를 하나 더 만드는 SQL을 Supabase SQL Editor에서 실행해야 한다. 실행하기 전에는 비밀번호 변경을 검증할 수 없다.
