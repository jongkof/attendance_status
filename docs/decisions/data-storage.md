# 데이터 저장소

## Decisions

- 근태 기록, 팀원 명단, 이후의 휴일·행사·면담·발송 데이터는 Supabase(호스팅 Postgres)에 저장한다.

- 실명 근태를 Supabase·Vercel 같은 외부 서비스에 저장하는 것은 사내 정책에서 허용되는 것으로 사용자가 확인했다(2026-10-30). 시험 단계의 마스킹 이름(성+ㅇㅇ)은 명단 관리 화면에서 사용자가 직접 실명으로 고친다. 실명을 저장소·커밋·문서에 넣지 않는다.

## Boundaries

- 브라우저 저장소나 서버의 로컬 파일을 공유 데이터의 원본으로 쓰지 않는다.
- 이 결정은 저장 위치만 정한다. 관리자 잠금 방식(로그인)은 따로 정한다.

## Why

관리자가 반영한 근태를 다른 팀원이 각자의 브라우저에서 봐야 하므로 서버 쪽 공유 저장소가 필요하다. 외부 서비스로 운영할 예정이라 배포 환경과 상관없이 데이터가 유지되어야 하고, 이후의 관리자 잠금과 예약 발송도 같은 서비스 위에서 이어 갈 수 있다.

## Reconsider when

- 사내 서버처럼 직접 관리하는 환경에서만 운영하게 되어 외부 호스팅 데이터베이스를 쓸 수 없을 때
- 회사 보안 정책이 근태 정보를 외부 데이터베이스에 두는 것을 막을 때

## Still-rejected alternatives

- 서버의 로컬 파일 또는 SQLite: 준비는 간단하지만 서버리스 환경에 배포하면 데이터가 사라진다. 직접 관리하는 서버에서만 운영하게 되면 다시 검토한다.
