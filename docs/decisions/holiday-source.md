# 휴일 데이터의 출처

## Decisions

- 휴일과 행사는 서비스가 직접 가진다. 외부 공휴일 라이브러리나 외부 공휴일 서비스를 호출하지 않는다.
- 회사 규정으로 날짜가 정해지는 휴일(근로자의 날, 회사창립기념일, 노조창립기념일)은 규칙으로 계산해 항상 보인다. 저장하지 않고, 관리자가 고치지 않는다.
- 정부 공휴일(설날·추석 4일, 대체공휴일 포함)과 회사가 임시로 정한 휴일, 사내 행사는 데이터베이스에 저장한 달력 항목으로 둔다. 처음에는 2026년과 2027년의 정부 공휴일을 공식 자료와 대조해 확인한 날만 넣고, 그 이후 연도와 임시공휴일은 관리자가 등록한다.
- 설날·추석은 회사 규정에 따라 명절 전일, 당일, 익일, 그 익일의 4일을 모두 휴일로 넣는다.

## Boundaries

- 이 결정은 휴일 데이터가 어디서 오는지만 정한다. 휴일이 현황표와 집계에 어떻게 나타나는지는 작업별 스펙이 정한다.
- 달력 항목을 한 번에 여러 건 입력하는 방법(템플릿, 프롬프트)은 이 결정에 들어 있지 않다.

## Why

한국의 공휴일은 음력 명절, 대체공휴일, 임시공휴일이 섞여 있고 회사는 설날·추석을 법정 연휴보다 길게 쉰다. 라이브러리는 이 규칙을 알지 못하고, 아래 근거처럼 날짜도 틀렸다. 데이터를 우리가 가지면 틀렸을 때 관리자가 바로 고칠 수 있고, 외부 서비스 호출이 늘지 않아 개인정보와 외부 서비스를 걱정하는 상황에 맞는다.

## Reconsider when

- 매년 공휴일을 입력하는 일이 부담이 되어 자동 가져오기가 필요해질 때(공공데이터포털의 특일 정보 API를 먼저 본다)
- `date-holidays`가 한국 음력 공휴일 날짜와 명절 연휴 앞뒤 날을 바로잡았을 때

## Still-rejected alternatives

- `date-holidays` 라이브러리 — 2026·2027년 추석이 하루 틀리고 명절 앞뒤 날이 없다. 위 재검토 조건이 생기면 다시 본다.
- 공공데이터 특일 정보 API — 가장 정확하지만 키 발급과 서버의 외부 호출이 필요하다. 수작업 입력이 부담이 될 때 다시 본다.

## Evidence worth preserving

- `date-holidays` 3.38.0의 `KR` 데이터는 2026년 추석을 9월 24일, 2027년 추석을 9월 14일로 돌려준다. 위키백과 「추석」은 각각 9월 25일(금)과 9월 15일(수)이다. 설날은 당일 하루만 돌려주고 명절 앞뒤 날은 없다. 지방선거일 같은 임시공휴일과 제헌절의 휴일 여부는 확인하지 않았다.
